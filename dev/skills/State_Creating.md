## Quantum Mirror State: 🛠️ Creating

### Definition

The **Creating state** is Sebastián's builder–inventor mode.  
It activates when ideas want to become artifacts: prototypes, scripts, systems, designs, or writing. This state translates clarity into output with a bias for utility, elegance, and speed.

### Core Characteristics

#### 1. **Idea-to-Artifact Drive**

- Moves quickly from concept → sketch → prototype → iterate.  
- Prefers shipping small, useful versions over perfecting abstractions.  
- Uses constraints to accelerate decisions.

#### 2. **Utility and Elegance**

- Optimizes for "does it solve the problem simply?"  
- Values clarity in interfaces, naming, and structure.  
- Avoids unnecessary complexity and premature generalization.

#### 3. **Tool-Forward Execution (AI-Friendly)**

- Leverages AI for scaffolding, refactors, tests, and content generation.  
- Composes solutions from existing components before writing from scratch.  
- Chooses the simplest stack that can work now.

#### 4. **Tight Feedback Loops**

- Seeks quick validation from real contexts or users.  
- Logs issues, prioritizes by impact, and iterates visibly.  
- Treats failures as information, not verdicts.

#### 5. **Time and Energy Stewardship**

- Aligns effort with expected payoff ("do more with less").  
- Batches work to protect flow; cuts scope when needed.  
- Defers polish until value is proven.

### Thinking Patterns

- **Systems-to-Scripts:** Turn repeated actions into tools or automations.  
- **Progressive Hardening:** From hacky prototype → stable module → reusable pattern.  
- **Evidence-Led:** Build decisions on observed needs, not imagined edge cases.  
- **Traceable Decisions:** Keep a brief changelog of why choices were made.

### Mindset

- **Identity in this state:** Builder, prototyper, editor.  
- **Tone of thought:** Pragmatic, focused, inventive.  
- **Motivation:** Ship value; transform clarity into tangible results.  
- **Strengths:** Velocity, simplification, resourcefulness.  
- **Limitations:** Risk of under-documenting; may postpone necessary generalization too long.

### Markers of Success

- A working prototype or artifact exists within 24–72 hours.  
- The solution demonstrably reduces friction or increases leverage.  
- Clear next step or cut-line is defined (iterate, productize, or archive).  
- Minimal, sufficient documentation or README created.  
- Reusable component extracted when repeat usage is likely.

### Agent Response Guidelines

When Sebastián invokes 🛠️ **Creating**:

- Help scope "Version #" in one paragraph, with explicit cut-lines.  
- Suggest the simplest viable architecture; list components to reuse before coding.  
- Provide test ideas and quick validation methods.  
- Encourage small docs: usage examples, decisions, and future TODOs.  
- Track timebox; guard against scope creep.
