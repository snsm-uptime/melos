# Tasks: Recipe Detail, Edit and Delete

**Input**: Design documents from `specs/027-recipe-detail-edit-delete/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/recipe-api.md, contracts/recipe-ui.md, quickstart.md

**Organization**: Grouped by user story (spec.md: US1 P1 read a recipe, US2 P1 edit, US3 P1 delete with confirmation, US4 P2 nothing left dangling). Phase 2 holds the errors, the write rule, the port additions, the access helper, the schemas and the ui client every story needs. Delete (US3) is its own phase so edit and read ship and test without it. There is **no migration** (plan: no schema change).

**Tests**: The spec does not request TDD, but constitution §6 requires domain tests, application tests with fakes and integration tests, so test tasks are included.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1, US2, US3, US4 (story phases only)
- Paths are repository-relative. api code runs from `api/`, so `domain/…` in code means `api/domain/…` on disk.

## Path Conventions

- api: `api/domain/`, `api/application/`, `api/adapters/persistence/`, `api/api/routes/`, `api/api/schemas/`, `api/tests/`
- ui: `ui/app/`, `ui/app/api/`, `ui/components/`, `ui/lib/`, `ui/lib/i18n/`
